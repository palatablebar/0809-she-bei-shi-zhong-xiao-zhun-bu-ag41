# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 在异常归因阶段查看每组的归属（设备漂移、基准跳变或证据不足）与受影响读数；证据冲突的分组保留不确定，不影响其他组的结论。
4. 修复来源文件，重新上传并执行。历史批次保留供复核；同一来源重跑不新增批次，迟到数据只生成新批次，不改写已签发结论。
5. 对账无差异、无坏行且异常全部完成归因时可签发（证据不足是合法终态，不强行归因）。对仍有差异的版本可填写暂缓意见。
6. 导出复核证据并保存于交接记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
